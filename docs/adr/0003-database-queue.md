# 0003. Queue στην PostgreSQL, όχι Redis

**Ημερομηνία:** 2026-10-09 · **Κατάσταση:** Αποδεκτή

## Απόφαση

Για τις Φάσεις 1–4, το Laravel queue χρησιμοποιεί τον **database driver**, στην ίδια PostgreSQL με τις πληρωμές.

## Γιατί

- Κάθε job είναι μια γραμμή σε πίνακα. Όταν κάτι κολλήσει, το βλέπω με ένα `SELECT`, και η διάγνωση με SQL είναι ακριβώς αυτό που θέλω να μάθω.
- Ο database driver τραβάει jobs με `FOR UPDATE SKIP LOCKED`, το ίδιο μοτίβο που θα γράψω μόνος μου στο outbox relay (Φάση 1). Θα το δω από δύο πλευρές.
- Ένα service λιγότερο να στήσω και να συντηρώ.

## Τι απέρριψα

- **Redis + Horizon** (προς το παρόν): πιο γρήγορο και με έτοιμο dashboard, αλλά κρύβει την κατάσταση των jobs μέσα σε ένα δεύτερο σύστημα.

## Τι κοστίζει

Κάθε job είναι writes και locks **στην ίδια βάση** με τις πληρωμές. Υπό φόρτο, το queue ανταγωνίζεται τις πληρωμές για συνδέσεις, locks και I/O.

## Πότε θα άλλαζα γνώμη

**Στη Φάση 5, σκόπιμα:** τρέχω το ίδιο φορτίο με database queue και με Redis, μετράω, και κρατάω ό,τι δείχνουν οι αριθμοί.

> Το **outbox δεν είναι** το Laravel queue. Το outbox είναι δικός μου πίνακας που γράφεται στο ίδιο transaction με την πληρωμή. Ο relay του μπορεί αργότερα να βάζει jobs στο queue.
