# 0002. Όλο το περιβάλλον μέσα στο Docker

**Ημερομηνία:** 2026-10-09 · **Κατάσταση:** Αποδεκτή

## Απόφαση

Όλα τρέχουν σε **Docker Compose**: nginx, PHP 8.5-FPM με Composer, PostgreSQL. Καμία εντολή του project (`composer`, `artisan`, `pest`) δεν τρέχει στον υπολογιστή μου, μόνο μέσα στο container. Το PHP container τρέχει με το δικό μου UID/GID.

## Γιατί

- **Ίδιο περιβάλλον παντού:** τοπικά, στο CI και αργότερα στην παραγωγή, η ίδια έκδοση PHP, τα ίδια extensions, η ίδια βάση (dev/prod parity).
- Στη Φάση 2 έρχονται mock bank και demo eshop. Ένα `docker compose up` σηκώνει όλο το σύστημα.
- **nginx + PHP-FPM** (όχι Octane / FrankenPHP): στη Φάση 5 θέλω να δω τα κλασικά προβλήματα της PHP υπό φόρτο (γεμάτα `pm.max_children`), όχι τα ειδικά προβλήματα του worker mode.

## Τι απέρριψα

- **Εγκατάσταση στον υπολογιστή:** κάθε μηχάνημα θα είχε άλλη έκδοση, και το CI θα ήταν διαφορετικό από το local.
- **Laravel Sail:** είναι έτοιμο compose για Laravel, αλλά κρύβει το setup. Θέλω να γράψω και να καταλαβαίνω κάθε γραμμή του Dockerfile και του compose.

## Τι κοστίζει

- Κάθε εντολή είναι μεγαλύτερη (`docker compose exec gateway …`).
- Χρειάζεται γνώση Docker που δεν είναι ο στόχος του project.
- Σε Linux, χωρίς σωστό UID/GID, τα αρχεία που φτιάχνει το container ανήκουν στον root.
- Ρυθμίσεις που ζουν σε δύο σημεία (`.env` ρίζας και `.env` του Laravel) μπορούν να αποκλίνουν. Συνέβη ήδη με τον κωδικό της βάσης.

## Πότε θα άλλαζα γνώμη

Αν το Docker γινόταν εμπόδιο στη μάθηση αντί για βοήθεια, π.χ. αν περνούσα περισσότερο χρόνο στο να το διορθώνω παρά στον κώδικα του gateway για αρκετές εβδομάδες.
