# 0004. Ένα repo για όλες τις εφαρμογές

**Ημερομηνία:** 2026-10-09 · **Κατάσταση:** Αποδεκτή

## Απόφαση

Το gateway, το mock bank και το demo eshop ζουν στο **ίδιο repo**, στο `apps/<όνομα>`.

## Γιατί

- Ένα `docker compose up`, ένα CI, ένα σημείο για issues και PRs.
- Όταν αλλάζει το «συμβόλαιο» ανάμεσα σε δύο εφαρμογές (π.χ. το API του mock bank), η αλλαγή γίνεται σε **ένα** PR που φαίνεται ολόκληρο, αντί για δύο PRs σε δύο repos που πρέπει να γίνουν merge με τη σωστή σειρά.

## Τι απέρριψα

- **Ένα repo ανά εφαρμογή:** για έναν developer είναι κόστος χωρίς όφελος (τρία CI, τρεις εκδόσεις, συγχρονισμός αλλαγών).

## Τι κοστίζει

- Το CI τρέχει **τα πάντα σε κάθε PR**, ακόμα κι αν άλλαξε μόνο μία εφαρμογή. Όταν μπει δεύτερη εφαρμογή, θα χρειαστεί φιλτράρισμα ανά φάκελο (`paths` στο GitHub Actions).
- Το `.gitignore` και τα εργαλεία πρέπει να γράφονται για πολλούς φακέλους (π.χ. `vendor/` χωρίς `/` στην αρχή).

## Πότε θα άλλαζα γνώμη

Αν μια εφαρμογή αποκτούσε δική της ομάδα και δικό της ρυθμό εκδόσεων. Για ένα προσωπικό project, ούτε μια εφαρμογή σε Python δεν θα αρκούσε για να τη βγάλω έξω.
