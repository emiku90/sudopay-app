# 0005. Merge commit για τα PRs

**Ημερομηνία:** 2026-10-09 · **Κατάσταση:** Αποδεκτή

## Απόφαση

Τα PRs μπαίνουν στο `main` με **merge commit**. Το ruleset επιτρέπει μόνο αυτή τη μέθοδο.

## Γιατί

- Κρατάει **όλα** τα commits του PR. Ένα PR με 5 μικρά commits μένει 5 μικρά commits, και το `git bisect` μπορεί να βρει ακριβώς ποιο έσπασε κάτι.
- Το merge commit δείχνει καθαρά πού ξεκίνησε και πού τελείωσε κάθε PR.

## Τι απέρριψα

- **Squash merge:** όλο το PR γίνεται ένα commit. Καθαρό ιστορικό, αλλά χάνεται η λεπτομέρεια, και το `bisect` σταματάει στο επίπεδο του PR.
- **Rebase merge:** γραμμικό ιστορικό, αλλά ξαναγράφει τα commits και χάνεται το όριο του PR.

## Τι κοστίζει

Ό,τι commit μπει στο PR, μένει **για πάντα** στο `main`. Commits όπως «fix typo», «oops», ή με λάθος μήνυμα (συνέβη ήδη στα πρώτα PRs) γίνονται μόνιμος θόρυβος. Ο κανόνας λοιπόν: **τα commits καθαρίζονται πριν το push** (`git commit --amend`, interactive rebase), όσο είναι ακόμα τοπικά.

## Πότε θα άλλαζα γνώμη

Αν δεν καταφέρω να κρατάω καθαρά commits μέσα στα PRs. Τότε το squash είναι καλύτερο από ένα ιστορικό γεμάτο θόρυβο.
